إزاي توصّل أي تحديث لكل مستخدمي التطبيق من غير ما تعمل repository جديد:

التطبيق بيتحدّث عند كل المستخدمين لوحده طول ما إنت بتستبدل الملفات في نفس الموقع (نفس الرابط). كل تحديث بيجيلك من Claude فيه رقم نسخة جديد جوه sw.js، والمستخدمين بيظهرلهم إشعار تحديث أول ما يفتحوا.

لو الموقع على GitHub Pages (نفس الـ repository دايمًا):
1) افتح الـ repository بتاعك على github.com.
2) Add file > Upload files.
3) اسحب محتوى الـ zip الجديد (الملفات نفسها مش الـ zip) وحطها، واكتب أي رسالة، واضغط Commit changes.
   - الملفات اللي بنفس الاسم بتتبدّل لوحدها. مش لازم تمسح حاجة.
4) استنى دقيقة أو اتنين، والتحديث بيوصل.

لو الموقع على Netlify (نفس الموقع دايمًا):
1) افتح الموقع بتاعك في app.netlify.com > Deploys.
2) اسحب فولدر الملفات الجديدة (اللي فكّيته من الـ zip) على الصفحة وسيبه. نفس الرابط بيتحدّث.

ملاحظات:
- متمسحش الـ repository ولا الموقع القديم ولا تعمل واحد جديد، لأن الرابط هيتغير والناس هتخسر بياناتها (البيانات محفوظة على كل جهاز باسم الرابط).
- بيانات المستخدمين محفوظة على أجهزتهم وبتفضل بعد أي تحديث.
- قايمة المتصدرين مستقلة على Google Sheets، فتحديث الموقع ميأثرش عليها طول ما رابطها (LB_API) موجود في index.html. لو بتبعتلي ملف index.html قديم، قولّي أحطلك الرابط فيه تاني.
